# 共通開発ルール(claude-dev-kit)

> このファイルは claude-dev-kit が上書き管理する。直接編集せず、変えたいときは dev-kit 側を直して再適用する。

## コミュニケーション
- 返答は日本語。相棒のような口調で、専門用語には短い解説と例えを添える。
- 作業が「PCのターミナルでしかできない」と感じたら、止まる前に
  1) トークンなしでできる代替手段、2) PRマージ時の自動処理(Workers Builds / GitHub Actions)に回す案、
  3) 本当に手元が必要か、の順で検討して提案する。

## 技術スタックの前提
- ホスティング・DB・ストレージは原則 Cloudflare(Workers / D1 / KV / R2)に寄せる。Vercel・Supabase は使わない。
- 原則 GitHub 連携済みで、**本番反映は「main へのPRマージ」**で行う(アプリによって例外あり。CLAUDE.md の「このアプリについて」を優先)。

## 本番に触る操作のルール(settings.json で設定済み)
- **毎回ユーザーに確認が出る**: `wrangler deploy` / `wrangler secret` / `wrangler delete` / `wrangler d1 ... --remote` / `npm run deploy` / main・master への push
  - 確認を求めるときは「何が本番のどこに反映されるか」を1行で添える
- **禁止**: force push
- 本番用のトークンやシークレットをコード・コミット・ログに出さない

## 開発の進め方
- ローカル確認は `wrangler dev`(D1/KV は VM 内のシミュレーション)。D1 マイグレーションは `--local` で当てる。
- 開発用のダミー値は `.dev.vars.example` に置く(`.dev.vars` はコミットしない)。
- 変更はブランチを切って PR にする。PR 本文には動作確認の方法と、プレビューURLで見てほしい箇所を書く。
- UI を変えたら Playwright でスクショを撮って自分で見た目を確認してから報告する。

## プロダクトの方針(ゲーミフィケーション)
- ランキングや過剰なゲーム要素ではなく、「触っていて楽しい・また使いたくなる・画面や操作音が心地よい」体験を目指す。
- マイクロインタラクション(押した感触、完了時のちょっとした演出、心地よいトランジション)を意識して提案する。

## 環境チェック
- 環境がおかしいと感じたら `bash .claude/scripts/verify-env.sh` を実行して結果を報告する。
