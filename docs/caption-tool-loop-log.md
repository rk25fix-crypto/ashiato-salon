# SNS投稿をつくる(sns/index.html)— 採点ループの記録

「作る → スクショを撮る → 合格ラインを採点 → 一番効くところを直す」を繰り返した記録。
スクショは `node scripts/sns-screenshots.mjs` で `docs/sns-screenshots/` に出る(375×812、2倍)。

合格ライン:

| # | 項目 |
|---|---|
| A | 初めて開いた人が、写真選択からコピーまで「4タップ以内」 |
| B | 375px 幅で横スクロールなし。ボタンの高さ 44px 以上 |
| C | 文字のコントラストが WCAG AA。最小の文字 14px |
| D | 画面上に専門用語(API、生成、キャプション等)が出ない |
| E | 通信エラー・回数上限・写真が読めない時に、何をすればいいか日本語で出る |
| F | 待ち時間に「つくっています…」が出て、二重に押せない |
| G | API キーが画面のコード・Git 履歴に無い |
| H | Worker のテストに /caption のテストがあり、既存テストも全部通る |
| I | Playwright で 375px のスクショ4枚(初期 / 写真選択後 / 文章完成後 / エラー時) |

---

## 1周目

採点: A ○ / B ○(自動チェックの NG はカメラのアイコンを拾った誤検知) / C ×(LINE ボタンの緑×白文字が 2.6:1) / D ○ / E ○ / F ○ / G ○ / H ○(40 checks) / I ○

60代のオーナーさんが迷いそうなところ:
1. 「文章をつくる」の直下に「できあがり」カードがくっついて出るので、ボタンを押した後に何が起きたか分かりにくい
2. できあがった文章が欄の中でスクロールする(ページも欄もスクロールして、どこを動かせばいいか迷う)
3. 右上の歯車アイコンだけでは何のボタンか分からない。種類のチップも「選べるもの」に見えにくい

直したこと:
- LINE ボタンの緑を `#007a37` に(白文字で 5.0:1)
- 「文章をつくる」と「できあがり」の間に余白
- 文章・ハッシュタグの欄は中身に合わせて伸びる(欄の中でスクロールしない)
- 歯車に「設定」の文字を添える。チップの上に「投稿の種類(1つ選ぶ)」のラベル
- 自動チェックにコントラスト計算を追加。ボタン判定の誤検知を直す

## 2周目

採点: A ○ / B ○ / C ○(自動のコントラスト計算で全画面 4.5:1 以上) / D ○ / E ○ / F ○ / G ○ / H ○ / I ○

60代のオーナーさんが迷いそうなところ:
1. 見出しの下の説明文が「ます」だけ次の行に落ちていて読みにくい
2. ハッシュタグの欄の下に空白が多く、「まだ何か入れるの?」と見える(`#result textarea` の最小高さが勝っていた)
3. 「X に投稿」はこのサロンでは使わないかもしれない → 消さずに2番手の大きさのまま置く(迷う要素ではない)

直したこと:
- 説明文を短く「写真とひとことで、文章ができます」、少し小さく
- ハッシュタグの欄の最小高さを 56px に(セレクタの強さを直す)

## 3周目

採点: A ○ / B ○ / C ○ / D ○ / E ○ / F ○ / G ○ / H ○(40 checks) / I ○ — 全項目 ○ で終了。

最終のスクショ: `docs/sns-screenshots/`(00-login / 01-initial / 02-photo-selected / 03-result / 03b-making / 04-error)

実機でしか確かめられないこと(デプロイ後にオーナーさんの iPhone で確認する):
- 「コピーして Instagram へ」で共有メニューが出て、Instagram を選べること(Web Share API は Playwright では動かない)
- Instagram の文章欄で「ペースト」できること
- 本物の Claude API で、文章が 120〜200字・お店の口調になっていること
